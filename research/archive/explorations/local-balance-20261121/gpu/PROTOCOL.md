# Conditional GPU inference experiment

The main-study development bounds improved by roughly four orders of magnitude, triggering the preannounced efficiency extension. This experiment is separate from the 80-parameter PB confirmation and does not establish that larger models are necessary for Idea 4.

A separate project environment uses official CUDA 12.8 PyTorch 2.7.1. No existing research runtime is replaced. The device is the user's RTX 5070 Ti. Fix ordinary MLPs with two tanh hidden layers of widths 64, 256 and 1024, three independent seeds per width. Each model uses the same 1024 training observations within a seed, ordinary Adam at learning rate 0.001 for 1000 full-batch updates, and binary cross entropy. Training labels come from the sampled mixture component. Training seeds are 971001--971003 and initialization seeds 972001--972003; no architecture or schedule is chosen by test outcomes. FP32, no autocast, TF32 disabled. Models with nonfinite states fail visibly. Save weights, data, and losses before calibration or testing.

Fit the unchanged invariant folded gate on 4096 new IID inputs and their antipodes (8192 forwards, seed 973000+seed), separately for every width. Its input-only score permits one combined model call on all 256 originals plus the selected 64 partners. The same selected set is also evaluated with two sequential calls as an equivalence control. No partner output enters selection. Fit the existing radius-specific angle table on 64 radii times 128 angular views (8192 forwards; radii 974000+seed, phases 975000+seed). This secondary policy uses first-view confidence and hence genuinely requires two sequential calls.

Policies: raw; full half-turn with sequential calls; optimized full half-turn with a combined 512-input call; confidence half-turn; folded half-turn with sequential calls; folded half-turn with a combined 320-input call; confidence plus calibrated radius-specific angles. Every limited policy selects exactly 64 per batch of 256. Forward-example count and actual invocation count are distinct. The fastest equivalent full implementation is the cost comparator.

Evaluate 16384 independent IID test inputs per model (976000+seed) with independent folded-score tie keys (977000+seed). Preserve expected and sampled-label logistic risk, classification error, all output and selection arrays, and per-policy call counts. Test posterior information is used only for evaluation. A model with low angular disagreement may offer little prediction benefit; keep that result.

Benchmark after the main CPU jobs have finished. Report FP32 GPU-resident wall and CUDA-event time, and synchronized CPU-input-to-CPU-output latency including transfers. Also benchmark the identical frozen models with one CPU thread for context. Use 16 real batches, three warmups and seven retained repetitions, with randomized policy order. GPU timing synchronizes around measurements and includes sorting, routing, gathers, rotations and scatter updates. Training, fitting, test scoring and warmups are excluded from deployment latency and itemized separately. The model and calibration tables remain resident; the transfer condition moves each actual input batch, needed tie keys and output logits.

Use three trained models per width as descriptive replications. Timing repeats are not independent model samples. A measured improvement is limited to this workload, precision, batch size and machine. Report calibration amortization only when the candidate actually saves wall time against the fastest full reference, and give both quality and cost. Do not fabricate a break-even for a slower method. Model width is a legitimate fixed architecture sweep, not repeated unused operations added to manufacture cost.

Independent sampled labels use seed 978000 + seed. Timing order uses 978100 + seed + width. These namespaces were moved before the GPU freeze to avoid overlap with selector development.
