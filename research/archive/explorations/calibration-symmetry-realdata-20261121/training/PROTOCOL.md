# Training and independent temperature calibration protocol

This branch keeps the preceding two-amplitude task and its 144-parameter residual architecture byte-identical. Inputs, group action, exact partner, label law, and balanced training sampler are unchanged. The synthetic posterior is used to generate sampled labels and later to evaluate expected risks; it is never an input to model selection, regularization fitting, early stopping, or temperature calibration.

## Fixed development search

Four pilot train/init/validation seed triples are 2091001–2091004, 2092001–2092004, and 2093001–2093004. Each has 256 training observations (128 per class by the existing class-conditional sampler) and 2,048 independent iid validation observations with sampled labels. Each of nine PB and nine GD trajectories is run on each seed, for 72 trajectories. PB learning rates are 2, 4, 8; GD rates are 0.1, 0.3, 1.0. Both use regularization strengths 0, 0.001, 0.01 and checkpoints 100, 250, 500, 1000. There is no architecture search and no task-law tuning.

The objective is mean sampled-label logistic loss plus `(lambda/2) sum of squared A and B matrix entries`. Biases are excluded. For GD the complete objective gradient is used. For PB the complete gradient is multiplied by the inverse of the existing full-output-Jacobian Gram sum plus 0.1 times identity. Thus the regularizer is inside the pullback solve; this is not ordinary weight decay applied after a data-only update. The unregularized legacy update is unchanged.

Within each trajectory select the checkpoint with minimum sampled-label validation log loss, ties preferring earlier checkpoints. Within each optimizer choose the hyperparameter pair with lowest mean of the four selected validation losses. Exact ties prefer lower mean selected step, then lower lambda, then lower learning rate. A failed trajectory makes its recipe ineligible; all failures and completed checkpoints remain. The development winner's validation loss is selected and optimistic, so it is not confirmation evidence. Both optimizers get the same sample counts, maximum updates, number of hyperparameter recipes, and validation looks; wall-clock cost differs and is recorded.

## Confirmation and calibration

Before fresh data generation, freeze the complete source and chosen PB/GD hyperparameters. Sixteen fresh replications use bases 2101000 train, 2102000 initialization, 2103000 validation, 2104000 temperature calibration, 2105000 selector calibration, 2106000 performance inputs, 2107000 ties, and 2108000 sampled performance labels, each plus pair index 1 through 16. All three model families share training inputs and initialization within a replication. The legacy model is unchanged PB4/500 with no validation selection. The selected PB and GD hyperparameters use fresh 2,048-label validation data and the same fixed early-stopping checkpoints. Each family is retained both raw and temperature calibrated, yielding six variants. Every family uses the same independent 2,048-label temperature sample.

Temperature fitting minimizes sampled-label logistic loss in positive inverse temperature beta=1/T on `[exp(-3),exp(3)]`. This objective is convex in beta; its derivative is monotone. Choose a boundary if its derivative has the correct sign there, otherwise use 80 fixed bisection iterations. The temperature function receives only precomputed logits and labels. It never accesses the posterior or performance data. Positive temperature preserves the raw classification sign at threshold 0.5, but temperature can change allocation scores and consequently a selective-averaging policy's classification decisions.

The newly selected training procedure consumes 256 training labels and 2,048 validation labels. A calibrated variant additionally consumes 2,048 independent calibration labels. It is not compared as having the same total label budget as legacy raw PB4/500. Validation and calibration draws are shared across model families for paired comparisons. Their model-forward costs are recorded; label acquisition is separate from deployment calls.

## Deployment and evaluation

Each variant uses raw prediction, full half-turn averaging, the preceding strong folded histogram (16×16×16 bins, frozen empty-cell fallback), and multilinear half-turn-even Jensen interpolation. Each selector has the same standalone 65,536-forward calibration budget: the interpolation grid is 16×16 amplitudes by 256 angles, and histogram calibration uses 32,768 iid input/partner pairs. Base-network logits may be shared between raw and temperature variants, but calibrated Jensen scores are recomputed from scaled logits; standalone equivalent costs and actual shared calls are both reported. No unqueried partner prediction is used at deployment. A quota policy executes exactly 256 original and 64 partner examples per batch, while raw and full references cost 256 and 512 respectively.

The primary comparison is selected PB plus temperature versus legacy PB raw, decomposed into training and temperature effects. GD is a matched search-budget context control, not assumed competitive. Evaluate all 16 replications and all six variants with the same 65,536 iid performance inputs per seed. Report expected and sampled-label log loss, classification error separately, Brier loss, fixed-bin reliability, and symmetry allocation gains. Selection and calibration parameters are immutable before performance evaluation. All comparisons are paired at the model-seed level; batches are not independent model replications. Positive temperature calibration is established prior work, not a novelty claim.
