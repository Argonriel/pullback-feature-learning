# Equal labeled budget and final-pipeline calibration

This prospective confirmation keeps the two-amplitude synthetic task and 144-parameter residual architecture unchanged. Previous studies provide fixed development choices only. There is no new hyperparameter pilot, architecture search, label-law change, or fresh-outcome selection.

## Three allocations of exactly 4,352 unique fitting labels

1. `legacy`: 256 balanced training examples; fixed PB rate 4, damping 0.1, 500 updates; 4,096 independent iid temperature-calibration labels; no validation selection.
2. `selected`: the same 256 training examples and initialization; fixed previous winning PB rate 2, damping 0.1, lambda 0, with 100/250/500/1,000 checkpoints selected by 2,048 independent sampled validation labels; 2,048 temperature-calibration labels.
3. `extra_train`: those same 256 examples plus an independent balanced 2,048-example sample, jointly shuffled, giving 2,304 training examples with exactly 1,152 per class; fixed 500-update PB recipe; 2,048 calibration labels and no validation selection.

The last procedure reallocates labels from calibration to training. Validation and calibration are disjoint within every procedure, and all calibration labels are independent of model training. The smaller calibration sample is the first 2,048 examples of the common 4,096-example iid calibration draw; this preserves pairing without exposing more fitting labels to that procedure. Sharing the same calibration labels across alternative scalar temperatures does not increase the number of unique fitting labels. Uncalibrated outputs are diagnostic arms with smaller actual label use: 256, 2,304, and 2,304 for the three families. They are not falsely labeled equal-budget calibrated procedures.

## Sample-size normalization

The original PB metric is a SUM over output-coordinate Jacobians, whereas the training loss is a MEAN. Keeping rate and damping numerically fixed as n grows would silently shrink steps. The extra-training arm therefore uses rate `4*n/256=36` and damping `0.1*n/256=0.9`. This is exactly the update with normalized metric `J.T@J/n + (0.1/256)I` and rate `4/256`. Duplicating all examples k times leaves the resulting update invariant when rate and damping both multiply by k. Preflight checks this at k=2,3,9 and verifies the analytic mean-loss gradient by independent finite differences. The mean-gradient GD update, although not a new study arm, is also checked to be invariant to duplication at fixed rate. No step-size claim relies on treating summed and averaged metrics interchangeably.

## Fixed pipelines and independent positive temperatures

Each base family has three prediction pipelines: original-view logits; full half-turn mean logits; and fixed input-only symmetric Jensen interpolation with exactly 64 partner calls per 256 inputs. The interpolation field uses the unchanged 16×16×256 raw-logit grid (65,536 forwards per base model). It is committed before temperature fitting and is never recomputed after temperature scaling. The model, scores, mask, tie rules, and quota are held fixed across all calibration arms.

Fit three independent positive scalar inverse temperatures per base model using sampled calibration labels: beta_raw for raw pipeline outputs, beta_full for full mean outputs, and beta_interp for the exact-quota pipeline outputs under independent calibration-batch ties. Each minimizes that pipeline's sampled-label log loss over [exp(-3),exp(3)] with the existing convex derivative bisection. Each nonraw pipeline is evaluated uncalibrated, with beta_raw, and with its own beta. Raw has only uncalibrated and beta_raw arms because own and raw temperature are identical. This gives eight output arms per family, 24 per replication, and 384 total result rows.

Multiplying logits by a positive scalar after a fixed averaging rule equals averaging the scaled logits, but fitting that scalar against different final outputs generally gives a different optimum. Positive scaling preserves every fixed pipeline's classification signs; this is checked on all performance inputs. No calibration value is selected from test loss or the known posterior. The posterior is used only to generate sampled labels internally and to evaluate final expected risks.

## Four primary contrasts and scope

The primary expected-log-loss contrasts are (1) selected PB full-final-temperature minus full-raw-temperature; (2) selected PB interpolation-final-temperature minus interpolation-raw-temperature; (3) extra-training raw-temperature minus legacy raw-temperature; (4) selected PB raw-temperature minus legacy raw-temperature. Negative differences favor the first arm. Use 16 paired model-seed clusters, 20,000 bootstrap draws, and two-sided alpha 0.05/4 for each of these four prespecified contrasts. This is approximate finite-model bootstrap uncertainty, not a distribution-free certificate. All other comparisons and classification/Brier/reliability metrics are secondary and labeled accordingly.

The equality is in unique fitting-label count and fixed capacity, not wall-clock compute or number of updates selected. The three allocations answer different resource-allocation choices. Across all three procedures together the experimental union uses 8,448 unique fitting labels per seed (256 base training, 2,048 extra training, 2,048 validation, and 4,096 calibration); the procedure-specific budgets remain 4,352. Validation selection costs 8,192 forward examples per selected-family model and zero for the two fixed-step families. The synthetic quotient and posterior remain known to the evaluator; no real-data guarantee follows. This is a prospective test of final-pipeline calibration and label allocation, not a novelty claim for temperature scaling.
